# RFC-0002 — Variables de entorno manuales

## Regla
Nunca commitear secretos. En Vercel configurar desde el proyecto. `pnpm check:env` valida `.env.example`.

## A. Bloqueantes de producción (ERROR si faltan)
- `NODE_ENV=production`
- `HOST`, `PORT`
- `APP_PUBLIC_URL`, `PUBLIC_URL`, `ISABELLA_PUBLIC_URL` (HTTPS en producción)
- `ALLOWED_ORIGINS` (sin localhost en producción)
- `TRUST_PROXY` (1..10 o false)
- `DATABASE_URL` o `POSTGRES_URL` / `POSTGRES_PRISMA_URL` / `POSTGRES_URL_NON_POOLING`
- `BOOKPI_INTEGRITY_SECRET` (>=32, no placeholder, entropía >=96 bits)
- `GENESIS_ADMIN_API_TOKEN` (>=32)
- `GENESIS_HUMAN_APPROVAL_TOKEN` (>=32)
- `GENESIS_HUMAN_APPROVER_ID`
- `ISABELLA_CREATOR_PRINCIPAL_ID`
- En serverless: `ISABELLA_API_KEY_STORE` y `ISABELLA_FEDERATION_STORE` deben ser adaptadores durables (no memory/file)
- Supabase (si se usa): `SUPABASE_URL` + `SUPABASE_SERVICE_ROLE_KEY` + (`SUPABASE_ANON_KEY` o `SUPABASE_PUBLISHABLE_KEY`)

## B. Tokens operativos (recomendados, separados, no reutilizar valores)
- `OPS_API_TOKEN`
- `HSF_API_TOKEN`
- `GENESIS_PUBLIC_API_TOKEN`
- `HYPERCORE_API_TOKEN` / `HYPERCORE_API_KEY`
- `ISABELLA_API_KEY_PEPPER`
- `ISABELLA_FEDERATION_SECRET` (>=32)
- `ISABELLA_FEDERATION_VERIFY_TOKEN` (>=16)
- `ISABELLA_APPROVAL_PRIVATE_KEY_PEM`, `ISABELLA_APPROVAL_TRUSTED_PUBLIC_KEY_PEM`, `ISABELLA_APPROVAL_KEY_ID`, `ISABELLA_APPROVAL_TRUSTED_KEY_ID`, `ISABELLA_APPROVAL_TRUSTED_APPROVER_ID`

- `GEMINI_API_KEY`

- `VERCEL_OIDC_TOKEN`
- `OLLAMA_ENABLED=true`, `OLLAMA_BASE_URL`, `OLLAMA_MODEL`, `OLLAMA_API_KEY` (opcional)
- `ISABELLA_LOCAL_COMPAT_ENABLED=true`, `ISABELLA_LOCAL_COMPAT_BASE_URL`, `ISABELLA_LOCAL_COMPAT_MODEL`, `ISABELLA_LOCAL_COMPAT_API_KEY`
- `DEEPSEEK_APIKEY`, `DEEPSEEK_MODEL`
